## B. Model findings (Phase 3 vs native)

| ID | Step | Observation | Action | Status |
|---|---|---|---|---|
| NAT-13 | 4 | Simscape lumps network outputs, so a Simulink controller reading plant signals creates an artificial algebraic loop. A variable-step Memory delay caused solver chattering (it stalled at the 3 s traction step). | Convention: controllers at the Simulink↔Simscape boundary use a fixed-rate Unit Delay at their real update rate. Apply this to DC-Link logic too (NAT-08). | OPEN |
| NAT-14 | 0 | Phase 3 `n_str` (fault channel 7) counts parallel cell groups (nominal 12 = 2 per string), not strings. The name is misleading. | Native maps strings online = `n_str/2`. Rename or document in Phase 3. Confirm `P.sys.fault_nominal(7) = 12`. | OPEN |
| NAT-15 | 0 | `voltify_loco_system.slx` is not committed; it is generated by `build_loco_system`. Native benches rely on `P` from that build, and the MATLAB path is not persistent between sessions. | Add a `startup.m` (path + build if `P` is missing). Document in README. | OPEN |
| NAT-16 | 0 | The Phase 3 model has global zero-crossing detection disabled (warning on every compile). | Review whether intentional (speed) or should be enabled. | OPEN |
| NAT-17 | 0 | `locomotive_sys.ssc` default tables (11-point `I_tab`/`T_tab`) differ from `P.ax` (37-point). | Confirm which values the Phase 3 block actually uses. Native uses `P.ax`. | OPEN |
